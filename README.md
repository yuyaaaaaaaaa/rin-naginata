# 凛 — macOS 用 薙刀式 v18 入力エミュレータ

凛（英字表記は Rin）は、大岡俊彦氏が考案したカナ配列「**薙刀式**」（v18 トップ版）を macOS で使うための、メニューバー常駐アプリです。
Karabiner-Elements などの外部ツールは使いません。

> **配布形態について**：ビルド済みのアプリは配布していません。ソースコードを自分の Mac でビルドして使ってください（手順は下記）。

---

## 特徴

### 1. 同時打鍵を「重なりの割合」で判定する

**速く打っても崩れにくいこと**が、凛のいちばんの長所です。

薙刀式は、ほぼすべての濁音・拗音・外来音を同時押しで打つ配列です。そのため、エミュレータの使い心地は「**意図した同時押し**」と「**速く打ったときの偶然の重なり（ロールオーバー）**」をどう見分けるかで決まります。

凛は、「**重なり割合**」方式で判定します。

- 2つのキーが同時に押されていた時間 ÷ 後から押したキーの押下時間 ＝ 重なり割合
- この割合がしきい値以上なら同時押し、未満ならロールオーバー（順に打った）とみなす

単に「押している間に次を押したら同時押し」とする方式では、たとえば「し→る」を速く打って指が重なると「しょ」に化けます。重なり割合で判定すると、重なりが一瞬なら「しる」、しっかり重なっていれば「しょ」と区別できます。

判定が確定するまで出力を保留しますが、「これ以上待っても判定が変わり得ない時刻」を判定規則そのものから計算して確定させるタイマーを持っているので、保留による「もっさり感」は数十ミリ秒に抑えられています。

**出力は必ず押下順**です。キーは押した順に先頭から一つずつ確定させ、同時押しはその最初のキーの位置に出力します。複数のキーが重なって判定が入り組んだときでも、後から押したキーが先に出ることはありません。

### 2. しきい値は実際の打鍵ログの統計から決めている

判定の初期値は作者の実際の打鍵傾向（打鍵ログ）から調整してあり、そのうえで**自分の指に合わせて調整し直せます**。

- 判定結果ごとに「直後1.2秒以内に BS（訂正）が続いた割合」を測る
- 通常の推敲率（約10%）を大きく超える帯域＝誤判定、同程度＝正しい判定とみなす
- 両者をきれいに分ける物差しを探し、その境界にしきい値を置く

この分析から、単一の割合では分けきれない誤判定の帯があることが分かり、「**短い方のキーの押下時間を基準にした第2判定**」という補助判定が生まれました。ほかに、親指シフトの絶対重なり時間による救済、誤和音ガードなども同じ方法で調整しています。

すべてのしきい値は設定画面のスライダーで変更でき、ログ記録機能で自分の打鍵を同じ方法で分析することもできます。

### 3. 文字盤イメージ上で、配列も編集モードも見て直せる

設定ファイルを書き換えなくても、**キーボード図で確かめながら**配列と編集モードを変えられます。

設定画面の「文字盤エディタ」は、かな配列と編集モードをキーボード図の上に表示します。キーをクリックすれば、その場でかなや機能を変えられます。

薙刀式では、濁音・半濁音・小書き・拗音・外来音がすべて清音と同じ位置にあります。文字盤エディタはこの思想に沿っていて、**編集できるのは基本面とシフト面の清音配置だけ**です。百数十ある同時押しの定義は、マニュアルの法則（濁音＝逆手の人差し指ホーム、拗音＝イ段＋や行、外来音＝3キー同時、など）からすべて自動で導出されます。

紅皿の配列ファイル（`.bnz`）を直接読み込むこともできます。

### 4. 編集モードまで含めて「薙刀式」、そして編集モードは自由に変えてよい

**薙刀式 v18 を、配列から編集モードまでまるごと収録**しています。

薙刀式は文字の配列だけでなく、カーソル移動・選択・コピペ・再変換・記号を扱う「**編集モード**」まで含めて一つの体系です。凛は v18 公式マニュアルの編集モード（4面）を、Mac 向けのキー操作に置き換えて初期値として搭載しています。配列は一つ前の v17 にも、設定画面で切り替えられます。

同時に、編集モードは**各自が自分の書き方に合わせて自由に作り替えてよいもの**だと考えています。文字盤エディタでは、アンカーのキー（例：D＋F）を緑で示した面ごとにキーボード図が表示され、キーをクリックして一覧から機能を選ぶだけで割り当てを変えられます。一覧にない操作も `cmd+z`、`「年」`、`左*5` のような簡単な記法で書けます。作った定義はファイルとして保存・共有でき、他の人の定義を「プリセット」として読み込めます（作者の個人設定を例として同梱しています）。

### 5. Mac の実際の環境に合わせた細部

**Mac のふだんの使い方を崩さない**ように作っています。

- かな/英数の状態を入力ソースから自動判定
- 英数入力時、入力ソースが ABC（US 解釈）なら JIS の記号配置を補正し、かわせみ英字のような JIS ネイティブのソースなら干渉しない
- JIS と US で同じ文字になるキーは物理イベントをそのまま通すので、ブラウザのショートカット等にも支障が出ない
- ⌘・⌃・⌥ を押している間は QWERTY のまま

### 6. 単体で動き、ネットワークにつながらない

**軽く安心して使える**ことも大切にしています。

- メニューバーに常駐する単体のアプリで、Karabiner-Elements などの外部ツールは要りません
- ネットワークには一切接続しません
- 打鍵ログは、記録をオンにしたときだけ手元の Mac に保存され、iCloud にも同期されません
- 無償のオープンソース（MIT ライセンス）です

## インストール

ダウンロードしたソースを自分の Mac でビルドします。ターミナルにコマンドを貼り付けるだけで、初めてでも 10 分ほどで終わります。
**詳しい手順は [INSTALL.md](INSTALL.md) にまとめています**。

流れは次のとおりです。

1. 開発ツールを入れる（初回のみ）：ターミナルで `xcode-select --install`
2. このページの「Code」→「Download ZIP」でソースをダウンロードして展開する
3. 展開したフォルダでビルドする：`cd ~/Downloads/rin-naginata-main && ./build.sh`
4. できた `Rin.app` を起動し、システム設定 → プライバシーとセキュリティ の **アクセシビリティ** と **入力監視** の両方で「Rin」をオンにして、起動し直す
5. 日本語入力を **ローマ字入力** にする（凛はかなを「ローマ字のキー列」として日本語入力に送るため）

キー入力を受け取って変換するアプリなので、2つの権限は仕組み上必要です。凛はネットワークに一切接続しません。

> **注意**：ほかの配列エミュレータ（Karabiner-Elements の薙刀式設定、桔梗、Benkei など）と同時に使うと、入力が二重に変換されます。凛を使うときはそれらを止めてください。

## 使い方

### 基本

- メニューバーの**薙刀のアイコン**から、有効/無効の切替、設定、ログ記録、ログイン時の自動起動などを操作します。
- **F+G 同時押し**で英数入力、**H+J 同時押し**でかな入力に切り替わります。
- **V+M 同時押し**でエンター。
- スペースは「単独で押すとスペース（変換）、押しながら他のキーを押すとシフト」です（センターシフト、連続シフト可）。

配列そのもの（どのキーで何が出るか）は、大岡氏の公式マニュアルを参照してください。

**Mac への置き換えについて**：公式マニュアルの編集モードは Windows のキー操作を前提にしているので、次のように置き換えています。

- Home / End → ⌘← / ⌘→（行頭・行末）、ファイル末尾 → ⌘↓
- カタカナ / ひらがな変換 → F7 / F6（日本語入力の種類によらず効く）
- 再変換 → かなキー2回（macOS 標準の作法）。かわせみなど再変換のキーが違う日本語入力では、文字盤エディタで D＋F 面と C＋V 面の I キーの定義を変えてください（例：かわせみでキー割り当てを「macOS日本語入力」タイプにしている場合は `ctrl+shift+R`）
- 入力キャンセル → Esc 2回

### 編集モードを自分用に変える

設定画面の「編集モード」→「文字盤エディタで編集…」で、編集モードをキーボード図で確認・変更できます。

- 上のメニューで面（「D＋F を押しながら」「単打の操作キー」など）を選ぶと、その面の割り当てがキーボード図に表示されます。緑のキーがアンカーです
- キーをクリックすると、「機能を選ぶ…」の一覧（カーソル移動、選択、コピー・ペースト、再変換、記号、脚本・小説マクロなど）から割り当てを選べます。「この割り当てを削除」で外すこともできます
- 一覧にない操作は、記法で直接書けます：`「年」`（文字を出す）、`cmd+z`、`shift+8`、`左*5`（5回）、`Enter?`（?＝かな入力時のみ）、`key98`（キーコード指定）
- 「新しい面を作る…」で、好きな2キーをアンカーにした面を追加できます
- 「一覧で編集…」では、すべての定義を表形式で確認・編集できます（2キーの組み合わせなど、キーボード図に載らない定義もここで扱えます）

定義は `~/Library/Application Support/Rin/edit_mode.json` に保存されます。設定画面の「プリセット」から、次の定義に切り替えられます。切り替える前の定義は `edit_mode.backup.json` に退避されます。

- **公式準拠（薙刀式v18マニュアル）**：初期値
- **凛作者の設定例**：作者の個人設定（IJKL 式のカーソル移動、演算子記号の面、曜日・年月日を出す面〈D+V〉、矢印文字の面〈U+I〉、単打の T/Y＝「（」「）」など）
- **ファイルから読み込む…**：他の人が作った定義や、自分で保存しておいた定義

### 判定の調整とログ

設定画面のスライダーで同時打鍵のしきい値を変えられます。「初期値に戻す」でいつでも元に戻せます。

特定の打ち方でミスが出るときは、メニューの「ログをファイルに記録」をオンにして症状を再現すると、全打鍵（押した・離した時刻を 1ms 単位）と判定結果が記録されます。このログは同梱の検証ツールで再生でき、しきい値を変えたらどう判定が変わるかを確かめられます（「仕組み」参照）。

> **ログの扱いに注意**：ログには、記録中のすべての打鍵が残ります。打った文章を再現できる情報なので、パスワードや個人的な文章を打つ前にオフにしてください。ログは iCloud で同期されない `~/Library/Logs/Rin/` に保存されます。

### 配列の切り替えと変更

設定画面の「配列」で、同梱の配列を切り替えられます。

- **薙刀式 v18 トップ版（公式）**：初期値
- **薙刀式 v17 ベスト版**：一つ前の版。v18 との違いは、シフト面の「ね」と「め」の位置、Q の単打が「ヴ」であること、ヴ行の打ち方（v17 は Q＋半濁点＋2文字目、v18 は う＋濁点＋2文字目）

「文字盤エディタで編集…」で、基本面・シフト面の清音の配置を格子状のキーボード図の上で変えられます（キーをクリックしてかなを入力）。濁音・拗音などの面も、同じ図で確認できます。濁音などは、その配列のバージョンの法則に従って自動で再導出されます。配列はバージョンごとに別のファイル（`~/Library/Application Support/Rin/naginata_v18.json` など）に保存されるので、切り替えても編集内容は失われません。紅皿用の `.bnz` ファイルや、自分で作った `.json` を「ファイルを選択…」で読み込むこともできます。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 起動してもローマ字のまま（`rfl` のように素の文字が出る） | キー入力がアプリに届いていません。①アクセシビリティ**と**入力監視の両方が許可されているか確認し、アプリを再起動。②それでも直らなければ、ターミナルで `ioreg -l -w 0 \| grep SecureInput` を実行し、`kCGSSessionSecureInputPID` が表示されたら Mac を再起動（パスワード入力欄などが「セキュア入力」を握ったままになっている状態） |
| ビルドし直したら権限を再度求められた | 自分で署名し直したアプリは別物とみなされるため、正常です。許可し直して再起動してください |
| 二重に文字が出る | ほかの配列エミュレータが動いています。すべて止めてください |
| ブラウザのショートカットが効かない | かな入力のままです。F+G で英数に切り替えてください |
| 再変換が効かない | 日本語入力によって再変換のキーが違います。編集モードの I の定義を変えてください。Google日本語入力は再変換に対応していません |
| 特定の打ち方でミスが出る | ログを記録して、どの判定で起きているかを確認し、しきい値を調整してください |

## 仕組み（概要）

CGEventTap でキーイベントを受け取り、判定エンジンに押下・解放の時刻を渡します。確定したかなはローマ字のキー列として日本語入力に送り、編集モードはキー操作や文字を直接送ります。

| ファイル | 内容 |
|---|---|
| `src/Engine.swift` | 判定エンジン。OS のイベントや出力に依存しない純粋なロジック |
| `src/main.swift` | キー入力の受け取り、出力、配列・編集モードの読み込み、設定画面などアプリ部分 |
| `resources/layouts/` | 同梱の配列（v18・v17） |
| `resources/edit_presets/` | 同梱の編集モードプリセット |
| `tools/` | 判定エンジンの検証ツール |

**判定エンジンの考え方**

- キーを押した順に、先頭のキーから一つずつ確定させる。先頭のキーの相手は、配列上そのキーと組めるキーの中から探す
- 2つのキーが同時押しかどうかの規則（重なり割合、短い方基準の第2判定、親指シフトの絶対重なり救済）は一か所にまとめ、判定を確定させるタイマーの時刻も同じ規則から導く
- 編集モード（アンカー2キー＋3キー目）も同じエンジンで扱い、アンカーに使ったキーが後からかなの同時押しに使われることはない

**検証の仕組み**

`tools/engine_sim/` に、判定エンジンと一行ずつ対応する Python 版のシミュレータがあります。打鍵ログを再生して判定を比べたり、ランダムな打鍵で出力順の逆転や打鍵の取りこぼしがないかを監査したりできます。アプリ自体も `--replay` オプションで打鍵ログを再生できるので、Swift 版と Python 版が同じ判定をすることを `tools/verify_engine.sh` で確かめられます。

## 謝辞と出自

次の方々に心からの感謝を申し上げます。

- **大岡俊彦氏 — 薙刀式**
  「薙刀式」は、大岡氏の創作によるものです。
  薙刀式の詳細・最新版（v18）・公式マニュアルは、大岡氏のブログ「大岡俊彦の作品置き場」の[薙刀式の記事](https://oookaworks.seesaa.net/article/456099128.html)をご覧ください。

- **forestail氏 — 桔梗（[Kikyo](https://github.com/forestail/Kikyo)）**
  凛の判定エンジンは、桔梗の判定エンジンの次の手法を参考にして設計しています。
  - 重なり割合の分母を「後から押したキーの押下時間」とすること
  - 3キー同時押しの判定（3組すべてのペアが同時押しであるか、押下時間がそろっていて「3キーが同時に押されていた瞬間」があること）
  - 2キーの同時押しが3キーに伸びる可能性があるときに判定を待つこと
  - ごく短い重なり（12ms 未満）を同時押しとみなさない誤和音ガード
  - 連続シフト中のスペースを保持しておく扱い

- **Kenichiro_ayaki氏 — 紅皿（Benizara）**
  方向ごとに分けた重なり割合のしきい値（親指→文字、文字→親指、文字同士）、判定確定まで出力を保留する考え方（紅皿の「零遅延モード」オフに相当）、連続シフトといった判定パラメータの体系は、紅皿の設定項目に倣っています。初期しきい値の一部（60%）も紅皿での設定値を引き継いでいます。また、紅皿の配列ファイル形式（BNZ）を読み込めるようにしています。

※凛の独自の部分は、押下順に先頭キーを確定させる判定の進め方、短い方基準の第2判定、親指シフトの絶対重なり救済、判定規則から導く確定タイマー、しきい値の統計的な調整方法と検証ツール、v17/v18 の導出法則の実装、Mac 向けの編集モード・英数処理・文字盤エディタとなります。
